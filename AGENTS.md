# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## Language Policy (mandatory)

| Artifact | Language |
| --- | --- |
| Documentation (`README.md`, `docs/`, `AGENTS.md`, ADRs) | English |
| Code, identifiers, code comments, docstrings | English |
| Commit messages, branch names, PR titles and descriptions | English |
| Log messages, error messages, CLI/UI strings in source | English |
| Test names and test fixtures | English |
| Replies to the user in chat/conversation | **Korean** |

Rules:

- Everything written into the repository is English. No Korean text in tracked files,
  except for user-facing localization resources if the product later adds a Korean locale.
- Only conversational responses to the user are written in Korean. When quoting code,
  paths, commands, or identifiers in a Korean reply, keep them verbatim in English.
- If the user writes a requirement in Korean, translate it into English before recording
  it in docs, comments, task descriptions, or commit messages.

## Project Summary

Toodo is a task-planning app that turns a plan into implemented, reviewed code:

1. Register a **workspace**: a local directory or a remote directory on a saved herdr
   SSH machine.
2. **Plan** tasks inside a workspace. Tasks may depend on each other and form a DAG.
3. **Prepare** a task for implementation: create a dedicated `git worktree` in a separate
   directory through the herdr API.
4. **Implement** the task inside herdr (agent panes running in that worktree).
5. **Record** the commits produced (SHA, message, author, timestamp) against the task.
6. **Complete** the task: marking it done opens a pull request from the worktree branch.

See [`docs/architecture.md`](docs/architecture.md) for the domain model and
[`docs/workflow.md`](docs/workflow.md) for the task lifecycle.

## Platform and Stack

- **Target**: Windows desktop app (Windows 10/11). Other platforms are not a goal for now,
  but avoid needless Windows-only APIs outside platform adapters.
- **Prerequisite**: herdr is installed and running on the user's machine. Toodo is a
  companion app that controls herdr; it never installs, updates, or bundles herdr.
  Git, Windows OpenSSH (`ssh.exe`), and `gh` are also expected on `PATH`.
- **App shell**: Tauri 2 (WebView2), packaged as MSI/NSIS.
- **Backend**: Rust with tokio. Tauri commands exposed to the frontend with typed
  bindings generated by tauri-specta.
- **Frontend**: React, Vite, TypeScript, TanStack Query, Tailwind CSS, shadcn/ui.
- **DAG editor**: React Flow (`@xyflow/react`) with elkjs for automatic layout.
- **Storage**: SQLite via `rusqlite` in the app data directory.
- **Tests**: `cargo test` for Rust, Vitest for the frontend, fake adapters for herdr, git,
  ssh, and gh.

## Repository Status

The Tauri 2 scaffold is in place: the React frontend lives in `src/`, the Rust backend in
`src-tauri/`. Keep the **Commands** section below in sync with `package.json` scripts.

Layout:

- `src/`: React frontend. `@/` is an alias for `src/`.
  - `src/lib/bindings.ts`: TypeScript bindings generated by tauri-specta. Do not edit by
    hand; it is rewritten on every debug run of the app and by `cargo test`.
  - `src/components/ui/`: shadcn/ui components (add more with `npx shadcn@latest add <name>`).
- `src-tauri/`: Rust crate `toodo` (library `toodo_lib`).
  - `src-tauri/src/lib.rs`: Tauri builder and tauri-specta command registration.
  - `src-tauri/src/commands.rs`: Tauri commands exposed to the frontend.
  - `src-tauri/src/domain/`: core domain model and rules (task DAG, status transitions,
    slugs, worktree paths and branch names). Pure logic: no I/O, Tauri, or storage.

## Commands

Run from the repository root unless noted. Package manager is npm.

- Install: `npm install`
- Dev (full app): `npm run tauri dev`
- Dev (frontend only, browser): `npm run dev`
- Build installers (MSI/NSIS, on Windows): `npm run tauri build`
- Test (frontend): `npm test`
- Test (Rust, also regenerates `src/lib/bindings.ts`): `cargo test` in `src-tauri/`
- Typecheck (frontend): `npm run typecheck`
- Lint / format (Rust): `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check`
  in `src-tauri/`

After changing a Tauri command signature, run `cargo test` in `src-tauri/` and commit the
updated `src/lib/bindings.ts` together with the Rust change.

## Conventions

- Keep changes small and focused; one concern per commit.
- Commit messages: imperative mood, English, e.g. `Add worktree creation via herdr API`.
- Do not commit secrets, SSH keys, or host-specific paths. SSH targets and credentials
  come from user configuration, never from source.
- External integrations (herdr, git, SSH, Git hosting/PR API) go behind a thin adapter
  module so they can be faked in tests.
- Treat the task DAG as an invariant: reject edges that would create a cycle.

## Integrations

- **herdr** (required, preinstalled): terminal workspace manager for AI coding agents.
  - On startup, check that `herdr` is on `PATH` and the server responds (`ping` /
    `herdr status`); if not, ask the user to start herdr.
  - Commands go through the herdr CLI (`herdr worktree create|open|list|remove`,
    `herdr workspace focus`, `herdr agent prompt|wait`), which herdr recommends for
    portable Windows behavior. CLI output is the JSON `{"id", "result"}` envelope of the
    socket API; parse it as JSON, never scrape text.
  - Events come from the socket API (`events.subscribe`) over the Windows named pipe:
    `worktree.created`, `worktree.removed`, `pane.agent_status_changed`.
  - Remote workspaces map to saved herdr SSH machines (`herdr machine ...`).
  - Implementation happens in herdr itself; Toodo does not embed a terminal.
- **git**: run `git.exe` (not libgit2) for branches and commit history.
- **ssh**: run Windows OpenSSH `ssh.exe` for git commands on remote workspaces, sharing
  the user's `~/.ssh/config` and ssh-agent with herdr.
- **Git hosting**: GitHub only for now; pull requests are opened with the `gh` CLI when a
  task is completed.
